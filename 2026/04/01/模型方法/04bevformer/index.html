BEV Former架构图

BEVFormer核心内容：构建一个特征空间（bev queries）

需要根据自己的硬件条件来设置这个特征空间的大小

对于每一时刻摄像头捕获到的图像

取出图像经过resnet后的特征图，通过FPN后输出4个尺度的256维特征图

（假设P2大小为56×56 的特征图，P3大小为28×28 的特征图，P4大小为14×14的特征图，P5大小为7×7 的特征图）

6 个摄像头 ×4 个尺度 = 24 张特征图。这 24 张特征图被压扁成一维序列后，里面的每一个 Token（特征点）都必须被打上“三重基因”（2D 坐标、相机 ID、尺度 ID）

位置编码

二维平面，就有两个独立的坐标方向：宽方向的 x 和高方向的 y。

对于一个标准的 256 维特征向量，算法的策略：

  • 拿出前 128 维，专门用来记录 x 坐标的位置信息。
  • 拿出后 128 维，专门用来记录 y 坐标的位置信息。

并需要将不同尺度的256维特征图归一化后的网格坐标编码

PEx(x,2i)=sin⁡(x100002i/d)PE_x(x, 2i) = \sin\left(\frac{x}{10000^{2i/d}}\right) PEx​(x,2i)=sin(100002i/dx​)

横坐标位置 x 在特征向量中第 2i 个维度（偶数维度）上的绝对编码数值

PEx(x,2i+1)=cos⁡(x100002i/d)PE_x(x, 2i + 1) = \cos\left(\frac{x}{10000^{2i/d}}\right) PEx​(x,2i+1)=cos(100002i/dx​)

横坐标位置 x 在特征向量中第 2i+1 个维度（奇数维度）上的绝对编码数值

PEy(y,2j)=sin⁡(y100002j/d)PE_y(y, 2j) = \sin\left(\frac{y}{10000^{2j/d}}\right) PEy​(y,2j)=sin(100002j/dy​)

纵坐标位置 y 在特征向量中第 2j 个维度（偶数维度）上的绝对编码数值

PEy(y,2j+1)=cos⁡(y100002j/d)PE_y(y, 2j + 1) = \cos\left(\frac{y}{10000^{2j/d}}\right) PEy​(y,2j+1)=cos(100002j/dy​)

横坐标位置 y 在特征向量中第 2j+1 个维度（奇数维度）上的绝对编码数值

(注：这里的 d 就是 128，而 i、j 代表这 128 维里的第几个维度。)

当底层代码分别算出了 X 轴的 128 个数字和 Y 轴的 128 个数字后，直接首尾拼接 。

PE(x,y)=[PEx(x),PEy(y)]PE(x, y) = [PE_x(x), PE_y(y)] PE(x,y)=[PEx​(x),PEy​(y)]

最终生成256维的位置编码

相机ID编码

先初始化一个6乘256的权重矩阵，作用是判定FPN输出的特征图到底是来自于哪个相机。在每一次前向传播（Forward Pass）结束时，网络会在 BEV 鸟瞰图上预测 3D 边界框（包含坐标 x,y,z 和偏航角 θ），再通过反向传播在训练中一点点修正。

尺度编码

FPN 给出了 4 个不同分辨率的特征图（p2-5）。为了解决多尺度长宽不一的问题，我们把坐标归一化到了 [0,1] 之间。

但这引发了一个极其致命的物理 Bug：

  • 在 P2 层，归一化坐标偏移 Δx=0.01，在真实的物理世界（原始图片）里，可能只移动了 10 个像素（刚好从车标移动到车灯）。
  • 在 P5 层，同样的归一化坐标偏移 Δx=0.01，在真实物理世界里，直接跨越了 80 个像素（直接从车头跨到了车尾）

如果没有尺度编码，当 BEV Query 试图去图片上抓取特征，并算出一个微小的偏移量时，它面对这 4 张被压扁的 1D 序列，会彻底丧失“物理距离感”。

系统会开辟 4 个 256 维的随机向量，分别绑定给这 4 个层级。每一个都是【1，256】

它们隐式地 (Implicitly) 编码了特征图的“下采样步长 (Stride)”与“感受野大小 (Receptive Field Size)”

  • 对于第 0 号向量（绑定 P2）：网络在反向传播中发现，只要是带着这个 256 维密码的 Token，它里面的视觉特征都是极其细腻的。于是，这 256 个数字被强行优化成了一种“高频/细粒度先验 (Fine-grained Prior)”。
  • 对于第 3 号向量（绑定 P5）：网络发现带着这个密码的 Token，特征极其抽象宏大。这 256 个数字被优化成了一种“低频/全局上下文先验 (Global Context Prior)”。

用简单的加法代码 final_token = image_feature + pos_embed + cam_embed + level_embed，本质上是在做高维信息的终极缝合。它将纯粹的视觉语义（特征图）、数学计算出的 2D 绝对坐标（位置编码）、隐式学习到的相机物理外参（相机ID编码），以及感受野的多尺度层级（尺度编码），这四种截然不同的情报，强行压缩到了同一个 256 维的超级特征向量中。

在执行加法的前一瞬，数据面临着巨大的维度鸿沟。被展平的图像特征（例如 P2层）和对应的 2D 位置编码是巨大的矩阵，例如包含 3136 个特征点，形状为 [3136, 256]。而相机编码和尺度编码只是孤零零的一维向量 [256]。为了强行对齐，底层引擎会瞬间启动“张量广播”机制，将这两个极其短小的密码向量在内存里暴力复制 3136 份，膨胀成与图像特征尺寸完全一致的庞大矩阵

原因：

直接相加之所以不会把不同的信息搅成一锅粥，是因为在 256 维的极其广袤的高维空间里，矩阵加法本质上是一种向量的平移。原本纯粹的视觉特征并没有被污染破坏，而是被完美地平移搬运到了代表特定坐标、特定相机、特定尺度的“专属高维货架”上。得益于 Transformer 内部线性点积的强大解耦能力，它能够极其轻松地逆向拆解出这个向量里蕴含的全部四层身份信息。

最后将每一张256维特征图被展平为256维的“长条”（3136+784+196+49=4165，形状为[4165, 256]），这个拼好的 [4165, 256] 张量，被作为唯一的 Value（特征值）

一维张量:拼好的 [4165, 256]张量

空间形状矩阵：二维张量，形状通常是 [4, 2],记录了那 4 个特征图在被展平之前的真实高度和宽度

层级起始索引：一个长度为 4 的一维张量。记录了每一个尺度在[4165, 256] 张量里的绝对起始位置

BEV Encoder

Multi-Scale Deformable Attention流程概述

BEV Query：256维向量，将50乘50的 BEV Query（待优化），直接经过全连接和激活函数，得到采样的偏移量和注意力权重（待优化）。

用得到的偏移量对采样点进行偏移 。

偏移量预测 (4层 × 4点 × 2坐标)

而这个参考采样点是根据由几何关系固定的，网络只去优化这个偏移量

具体流程为：BEV 平面位置，配上n个高度 z 采样。然后把这些 3D 点通过相机外参/内参投影到各个相机视角，得到每个相机、每个尺度特征图上的初始参考位置，取q个采样点（q个注意力头），每个采样点再取p个偏移位置，因为这个偏移量可能是小数，所以会通过双线性插值，去得到偏移过后的特征图的那个点的值，对n个不同高度的点进行相同的操作，并进行加权融合

在每个尺度（feature level）的特征图上都进行上述采样和加权

最终得到bev query的一个256维向量

然后再通过网络训练，让其知道该从[4165, 256] 张量的哪一段取到自己想要的数据

对于每个 reference point：

  • 有 333 个 attention heads

Multi-Scale Deformable Attention（多尺度可变形注意力机制）-点对点

首先将偏置都初始化为0，图上展示了三个注意力头，每个注意力头采样三个点，每个点都需要一个2D平面的偏移坐标（x，y），利用反向传播对偏置进行调整

取出偏移后的点的位置对应的数值，进行加权融合，拼接输出

空间交叉注意力

  • 铺设网格 (BEV Queries)：系统首先在自车周围铺设一张巨大的 2D 鸟瞰图网格。网格上的每一个格子，就是一个查询向量
  • 升维成柱 (Pillar Lifting)：因为 2D BEV 没有高度信息，系统会把这个 2D 坐标沿 Z 轴（高度）向上拉伸成一根“柱子”，并在柱子上均匀采样n个 3D 空间参考点
  • 相机矩阵投影 (Projection)：利用第 i个相机的外参 Ti和内参 Ki，极其暴力地把这些 3D 点投影到对应的 2D 照片上，计算出它们在图像上的 2D 像素参考点

假设摄像头是六个，每个摄像头的图像为100*100，bev queries需要和每个图像上的点建立关系，因此会产生大量计算，为简化计算，会先将无关点mask掉

mask：

模型会把 BEV 上的一个 2D 网格点，顺着 Z 轴（高度）拉伸成一根柱子，并在柱子上采样几个 3D 参考点。然后，利用相机的内外参矩阵，把这些 3D 点投影回 6 张 2D 照片上

物理越界判定（Masking）：一旦投影出来的像素坐标 (u,v) 落在照片的边界之外，或者这个 3D 点在相机背后，就会生成一个 布尔值掩码 (Boolean Mask)，将这些点标记为 False

时序自注意力

基于自车运动的位姿对齐 (Ego-Motion Alignment)：系统会读取两帧之间自车的真实物理位姿变化（包含平移矩阵和旋转矩阵），利用双线性插值和网格采样（Grid Sampling），系统强行把上一帧的 BEV 特征图在物理空间上拽过来，旋转平移到当前帧的坐标系下，形成对齐后的历史特征图

BEV Decoder

encoder 负责生成整张 BEV feature map，decoder 负责从这张 BEV feature map 里“读出目标”，最后输出 3D 检测框

输入：BEV feature、object queries

object queries 的数量需要人为设定，它决定了 decoder 最多能输出多少个候选目标（候选预测数上限），维度要和模型主干维度一致（256）

Self-Attention

Self-Attention 的核心是：每个 object query 都会去看其他所有 query，判断“谁和我相关”，然后把别人的信息加权聚合回来。

所以对第 iii 个 query 来说，它不是只看自己，而是会和：

q1,q2,q3,…,qNobjq_1, q_2, q_3, \dots, q_{N_{\mathrm{obj}}} q1​,q2​,q3​,…,qNobj​​

全部交互。

Hungarian Matching

把预测和 GT 做匹配，BEVFormer 延续 DETR 风格，不是直接按顺序监督第 1 个 query、第 2 个 query，而是先做 Hungarian Matching。

因为 query 是“槽位”，没有固定说：

  • 第 1 个 query 一定预测第 1 个 GT
  • 第 2 个 query 一定预测第 2 个 GT

所以要先找到哪个 query 最适合对应哪个 GT

需要找到一个最优匹配

BEVFormer 是 query-based detection，decoder 会输出固定数量的 object queries，例如：

Nquery=900N_{\mathrm{query}} = 900 Nquery​=900

但一帧图像中的真实目标数量通常远小于这个数，比如：

Ngt=15N_{\mathrm{gt}} = 15 Ngt​=15

因此会出现两个问题：

  1. 哪 15 个 query 应该对应这 15 个真实目标？
  2. 剩下的大量 query 应该学什么？

BEVFormer 的做法是：

  • 先用 Hungarian Matching 找到最优的一对一匹配

  • 匹配到 GT 的 query 学真实目标

  • 没匹配到的 query 学背景（no object）

Lcls(i)=CE⁡(zi,citarget)\mathcal{L}_{\mathrm{cls}}^{(i)} = \operatorname{CE}(z_i, c_i^{\mathrm{target}}) Lcls(i)​=CE(zi​,citarget​)

其中：

  • ziz_izi​：分类头输出 logits
  • citargetc_i^{\mathrm{target}}citarget​：匹配后的目标类别，可能是真实类别，也可能是 no object

对于匹配到 GT 的 query：

Lreg(i)=∥b^i−bigt∥1\mathcal{L}_{\mathrm{reg}}^{(i)} = \left\| \hat{b}_i - b_i^{\mathrm{gt}} \right\|_1 Lreg(i)​=​b^i​−bigt​​1​

总损失

总体可写成：

L=λclsLcls+λregLreg\mathcal{L} = \lambda_{\mathrm{cls}} \mathcal{L}_{\mathrm{cls}} + \lambda_{\mathrm{reg}} \mathcal{L}_{\mathrm{reg}} L=λcls​Lcls​+λreg​Lreg​

反向传播（Backward）

这一步最关键。

有了总损失：

L\mathcal{L} L

就可以对模型里所有参数求梯度。

例如对某个参数矩阵 (W_Q)，自动求导会计算：

∂L∂WQ\frac{\partial \mathcal{L}}{\partial W_Q} ∂WQ​∂L​

同样也会对：

WK,  WV,  Wcls,  WregW_K,\; W_V,\; W_{\mathrm{cls}},\; W_{\mathrm{reg}} WK​,WV​,Wcls​,Wreg​

都求梯度。

例如：

Q1=q^1WQQ_1 = \hat{q}_1 W_Q Q1​=q^​1​WQ​

后面又有：

s1j=Q1Kj⊤s_{1j} = Q_1 K_j^\top s1j​=Q1​Kj⊤​

再后面有 softmax、加权求和、分类头、回归头、loss。

这些操作都是可微的，所以 loss 对最终输出的误差，可以一级一级链式传回去：

L→qiout→qicross→Qi→WQ\mathcal{L} \rightarrow q_i^{\mathrm{out}} \rightarrow q_i^{\mathrm{cross}} \rightarrow Q_i \rightarrow W_Q L→qiout​→qicross​→Qi​→WQ​

这就是链式法则。

参数更新

有了梯度之后，优化器就来更新参数。

比如 SGD 的形式是：

WQ←WQ−η∂L∂WQW_Q \leftarrow W_Q - \eta \frac{\partial \mathcal{L}}{\partial W_Q} WQ​←WQ​−η∂WQ​∂L​

其中：

  • η\etaη：学习率

如果用 AdamAdamAdam，本质也是沿着梯度方向更新，只是更新规则更复杂。

同理：

WK←WK−η∂L∂WKW_K \leftarrow W_K - \eta \frac{\partial \mathcal{L}}{\partial W_K} WK​←WK​−η∂WK​∂L​

WV←WV−η∂L∂WVW_V \leftarrow W_V - \eta \frac{\partial \mathcal{L}}{\partial W_V} WV​←WV​−η∂WV​∂L​

Wcls←Wcls−η∂L∂WclsW_{\mathrm{cls}} \leftarrow W_{\mathrm{cls}} - \eta \frac{\partial \mathcal{L}}{\partial W_{\mathrm{cls}}} Wcls​←Wcls​−η∂Wcls​∂L​

Wreg←Wreg−η∂L∂WregW_{\mathrm{reg}} \leftarrow W_{\mathrm{reg}} - \eta \frac{\partial \mathcal{L}}{\partial W_{\mathrm{reg}}} Wreg​←Wreg​−η∂Wreg​∂L​

更新一次后，这些矩阵就变成了“稍微更好一点”的参数。
